# 待理解指令

## Ninja 循环依赖排查

### 1. 复现循环依赖错误
```bash
/snap/clion/481/bin/cmake/linux/x64/bin/cmake --build /home/nuo/CLionProjects/DesktopPet/bin --target DesktopPet -j 3 2>&1 | head -30
```
输出示例：
```
ninja: error: dependency cycle: lib/libDataReadWriterModule.so -> lib/libDataManager.so -> ... -> lib/libDataReadWriterModule.so
```

### 2. 查看某个目标的完整依赖列表
```bash
cd /home/nuo/CLionProjects/DesktopPet/bin && ninja -t deps lib/libDataReadWriterModule.so 2>&1
```
`ninja -t deps` 输出 ninja 为指定目标解析出的完整依赖列表，包括来自 `build.ninja` 的静态依赖和来自 `depfile` 的动态依赖。

### 3. 查看链接器生成的 link.d 文件
```bash
cat /home/nuo/CLionProjects/DesktopPet/bin/Services/Module/Other/DataReadWriter/CMakeFiles/DataReadWriterModule.dir/link.d 2>&1
```
`link.d` 由链接器的 `-Wl,--dependency-file` 生成，记录链接时打开过的所有 .so 文件。如果不存在说明依赖信息来自缓存。

### 4. 查找所有 depfile（.d 文件）
```bash
find /home/nuo/CLionProjects/DesktopPet/bin -name "*.d" -type f 2>/dev/null | head -30
```
查找编译器和链接器生成的所有依赖文件。为空说明依赖信息全来自 `.ninja_deps` 缓存。

### 5. 检查 ninja 缓存文件
```bash
ls -la /home/nuo/CLionProjects/DesktopPet/bin/.ninja_deps /home/nuo/CLionProjects/DesktopPet/bin/.ninja_log 2>&1
```
- `.ninja_deps`：二进制文件，缓存 depfile 解析后的依赖关系
- `.ninja_log`：记录每次构建的耗时和命令哈希

### 6. 清理 ninja 缓存
```bash
rm -f /home/nuo/CLionProjects/DesktopPet/bin/.ninja_deps /home/nuo/CLionProjects/DesktopPet/bin/.ninja_log && echo "Cleaned ninja cache"
```
删除后重新编译，ninja 会从 depfile 重新解析依赖，生成正确的 `.ninja_deps`。

### 7. 重新编译验证
```bash
/snap/clion/481/bin/cmake/linux/x64/bin/cmake --build /home/nuo/CLionProjects/DesktopPet/bin --target DesktopPet -j 3 2>&1
```

### 8. 验证新缓存的依赖列表（对比）
```bash
ls -la /home/nuo/CLionProjects/DesktopPet/bin/.ninja_deps 2>&1; echo "---"; cd /home/nuo/CLionProjects/DesktopPet/bin && ninja -t deps lib/libDataReadWriterModule.so 2>&1
```
对比清理前后的 `.ninja_deps` 大小和依赖列表，确认循环依赖是否消失。

## 排查逻辑

```
ninja -t deps  →  发现目标存在异常依赖
       ↓
检查 build.ninja  →  排除 CMake 生成问题
       ↓
ls -la .ninja_deps  →  确认缓存文件存在且时间戳异常
       ↓
find *.d  →  确认 depfile 不存在，依赖全来自缓存
       ↓
rm .ninja_deps  →  清理缓存，重新编译
       ↓
ninja -t deps  →  验证新缓存正确
```
